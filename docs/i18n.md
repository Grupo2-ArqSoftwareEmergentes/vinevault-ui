# Account language

`core/i18n/I18nService` is the single signal-based language state (`es`/`en`). It initializes from `vinevault.preferred-language`, updates `html.lang`, and persists changes with a safe in-memory fallback when storage is unavailable. Language primitives live in `core/i18n/language.ts`; IAM re-exports them for existing callers.

`ProfileService.connectAccount()` is wired once at the root. A stored authenticated session and subsequent account changes hydrate `GET /api/v1/profile`, including routes outside Profile. New-account hydration is queued after synchronous workspace invalidation so login cannot cancel its own profile request. Concurrent reads share their in-flight request. Selecting a language updates the UI/storage immediately before PATCH. A failed PATCH restores the prior language only if the user has not selected another language since. Read/write revisions prevent stale responses from undoing the latest selection. Session invalidation cancels old requests; profile hydration does not reset an already-loaded workspace.

## Rendering

The `t` pipe in `I18nModule` reads the language signal, including in OnPush components and Material dialogs. Catalogs `locales/es.ts` and `locales/en.ts` use source-message keys (gettext style): a Spanish source is its own Spanish fallback, and an English source is its own English fallback. Add the opposite-language entry when introducing a new source key. Messages with changing values use named parameters such as `{name}` or `{count}`. Translate only interface keys; never pass user names, wine descriptions, typed drafts, or AI replies through translation. Unknown server messages are preserved verbatim rather than guessed or machine-translated.

Templates cover navigation/workspace menus, public account/onboarding, profile dialogs, overview, inventory/edit/import/export/movements, devices/alerts, spaces, quotas, billing/checkout and the assistant shell. Domain enum values, request field names, routes, role checks and form controls are not translated. A language change must not reset a form or close an overlay. Toasts retain source keys and translate at display time, so already-visible messages update without resetting their timeout.

Legacy Material snack-bar mutation feedback from inventory, cellars, devices/organizations and public-account Google actions now uses `NotificationService` too. Message parameters (including device names and pairing tokens) remain raw values; only interface text is translated. This keeps one feedback surface instead of mixing untranslated bottom snackbars with the top-right host.

`localizedDate` and `I18nService.date()` use `es-PE` or `en-PE`. Backend decimal money remains in soles (`S/`): language selection never converts currency or recalculates server totals. Monthly unit labels are localized separately.

## AI/backend boundary

Core HttpClient requests send the active `Accept-Language`. Assistant HTTP calls and the legacy streaming fetch also send it explicitly. Sommelier's client-generated prompt follows the selected language. JSON payloads do **not** add an undocumented language field: the assistant request schema forbids extra properties.

The current Core assistant system prompt in `app/assistant/applications/chat_service.py` explicitly forces Spanish and does not read the language header/profile. **Real English AI answers require a corresponding backend change.** Frontend dictionaries do not rewrite generated answers or fabricate a translated reply. Backend-authored error messages likewise require backend localization when they have no known frontend error-code/message key.

## Verification

Run `npm run i18n:check`, `npm test -- --watch=false` and `npm run build`. The i18n check parses Angular HTML templates and rejects literal interface copy or unknown literal translation keys, excluding an explicit list of brands, units and example values; icon/SVG code and child-component message inputs are not treated as plain UI text. Dynamic source keys still need focused tests (the wine schema has a complete label check). Language-specific tests cover storage/document state, live OnPush rendering, open dialog drafts, existing toasts, optimistic rollback, stale responses, stored-session hydration, account changes, unchanged soles and AI request headers/payloads. UI tests use Spanish as the default; raw role/status data assertions must continue using backend codes (e.g. `WAITER`, `EXPIRED`), not translated labels.
